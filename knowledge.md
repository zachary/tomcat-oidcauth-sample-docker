# Project Knowledge

## What this is

A repo for the **OpenID Connect Authenticator for Apache Tomcat** (Boyle Software) plus its sample web app and a Dockerized Tomcat for running it. OIDC login is implemented as a Tomcat Valve that extends the standard form-based authenticator and speaks the OIDC **Authorization Code Flow** (redirect to OP → callback at `/j_security_check` with a `code` param → token exchange → realm lookup by username claim).

Three logical parts (the two subdirs are **separate git repos**, each with its own `.git`):

- `tomcat-oidcauth/` — the authenticator library itself (Gradle, Java 8). Builds **two JARs**: `tomcat85` and `tomcat90` classifiers, since the Valve class differs per Tomcat major version.
- `tomcat-oidcauth-sample/` — sample WAR app (Maven) that demonstrates the authenticator.
- Root level — Docker packaging: `Dockerfile` (Tomcat 9.0.120-jdk8), `conf/server.xml` (HTTPS on 8443 with `conf/tomcat-https.p12`, keystore password `changeit`), `tomcat-users.xml` (admin / `mypassword`, manager-gui/admin-gui), `manager.xml`.

  The keystore holds a self-signed cert (CN=localhost; SANs: localhost, *.slim.show, 127.0.0.1, ::1; CA:TRUE) generated with keytool. The PEM copy is `conf/tomcat-https-cert.pem`, installed as a trusted root in the macOS system keychain (`sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain conf/tomcat-https-cert.pem`) — without that, Go clients on macOS fail with `x509: "localhost" certificate is not standards compliant` (macOS's phrasing for an untrusted self-signed cert). To regenerate the keystore use the **system** keytool (Java 8's can't rewrite PBES2 keystores): `keytool -genkeypair -alias tomcat -keyalg RSA -keysize 2048 -sigalg SHA256withRSA -dname "CN=localhost, OU=Development, O=Boyle Software, L=Local, ST=Local, C=US" -ext "SAN=dns:localhost,dns:*.slim.show,ip:127.0.0.1,ip:::1" -ext "BasicConstraints=ca:true" -ext "KeyUsage=digitalSignature,keyEncipherment,keyCertSign" -ext "ExtendedKeyUsage=serverAuth" -validity 3650 -storetype PKCS12 -keystore conf/tomcat-https.p12 -storepass changeit`.

## Commands

- Build the authenticator (from `tomcat-oidcauth/`): `./gradlew build` — or `./gradlew compileJava` (compiles both tomcat85 + tomcat90 source sets). Needs **Java 8** (pinned via `mise.toml`: `zulu-8.52.0.23`; run `mise install` first if not present). Version is `2.5.0` (in `build.gradle`).
- Build the sample app (from `tomcat-oidcauth-sample/`): `mvn package` → produces a WAR (packaging `war`, group `org.bsworks.catalina.authenticator.oidc`). Also requires Java 8.
- Run everything: `docker build -t tomcat-oidcauth . && docker run -p 8080:8080 -p 8443:8443 tomcat-oidcauth` (exposes 8080 HTTP, 8443 HTTPS). Copy the built authenticator JAR + sample WAR into `webapps/`/`lib/` to deploy.

## Key code locations

- `tomcat-oidcauth/src/common/java/org/bsworks/catalina/authenticator/oidc/` — all shared logic (token exchange, OP config discovery, JWKS, ID token validation).
- `tomcat-oidcauth/src/tomcat85/java/` and `src/tomcat90/java/` — version-specific Valve entry points: `org.bsworks.catalina.authenticator.oidc.tomcat85.OpenIDConnectAuthenticator` and `...tomcat90.OpenIDConnectAuthenticator`.
- Sample app:
  - `tomcat-oidcauth-sample/src/main/webapp/META-INF/context.xml` — Valve config with the `providers` list (Okta tenant `integrator-7683855.okta.com`, client `0oa16yzvczebemVW0698`, `noForm="true"`, `hostBaseURI="http://localhost:8080"`, `callbackPath="/callback"`). **Gotcha:** per-app context descriptors must live at `META-INF/context.xml` (root element `<Context>` wrapping the `<Valve>`) — `WEB-INF/context.xml` is silently ignored by Tomcat.
  - `tomcat-oidcauth-sample/src/main/webapp/WEB-INF/web.xml` — FORM auth-method, `/secure/*` protected with `CONFIDENTIAL` transport guarantee, login/error pages.
  - `tomcat-oidcauth-sample/src/main/webapp/WEB-INF/jsps/` — `login.jsp`, `error.jsp`, `home.jsp`, `secure-page.jsp`, `logout.jsp`.

## Conventions & gotchas

- **Java 8 only** (`sourceCompatibility`/`targetCompatibility = 1.8`); don't introduce newer APIs. Tabs for indentation (`.editorconfig`).
- **`providers` attribute syntax** (in `context.xml`/Valve config) is JSON-*like* but without double quotes around names/values; wrap a value in single quotes if it contains commas, curly braces, or whitespace (e.g. `name: 'Amazon Cognito'`). The issuer **must** include the scheme (`https://...`) or OP config loading throws `MalformedURLException` at deploy time.
- **Gotcha (`ClassNotFoundException` for `...tomcat90.OpenIDConnectAuthenticator` at deploy):** valves declared in `META-INF/context.xml` are instantiated by `ContextConfig` with the **Common classloader** (`digester.setClassLoader(ContextConfig.class.getClassLoader())` + `setUseContextClassLoader(false)`), which only scans `$CATALINA_HOME/lib` (and `CLASSPATH`). The authenticator JAR **must** be in `/usr/local/tomcat/lib/` **before Tomcat starts** — a copy inside the WAR's `WEB-INF/lib` is on the webapp classloader and is **not** consulted, so it does not help. Copying the JAR into a running container also does nothing until Tomcat restarts (the Common classloader caches its URLs at boot). Symptoms are a `SAXParseException` at the `<Valve>` start tag in `context.xml` with `Caused by: java.lang.ClassNotFoundException`. The `Dockerfile` already bakes the JAR into `lib/`, so a fresh `docker build` avoids this; manually deployed WARs need the JAR placed in `lib/` before `catalina.sh run`.
- The sample WAR deploys at the `/tomcat8-oidcauth-sample-1.0.0-SNAPSHOT` context (file `tomcat8-oidcauth-sample-1.0.0-SNAPSHOT.war`; context path = WAR filename). Its `web.xml` servlet mappings are context-relative (`/secure/page-a`), so URLs are `http://localhost:8080/tomcat8-oidcauth-sample-1.0.0-SNAPSHOT/secure/page-a`. **The WAR is deployed under its Maven artifact name on purpose**: the context path must produce the exact redirect URI registered in the Okta app, `http://localhost:8080/tomcat8-oidcauth-sample-1.0.0-SNAPSHOT/callback`. Renaming the WAR changes the redirect URI and you must update Okta to match.
- `hostBaseURI` does NOT include the context path; `callbackPath` is the form-action suffix (default `/j_security_check`). The valve sends `redirect_uri = hostBaseURI + contextPath + callbackPath`, so with `hostBaseURI="http://localhost:8080"` and `callbackPath="/callback"` the redirect URI is `http://localhost:8080/tomcat8-oidcauth-sample-1.0.0-SNAPSHOT/callback`. **Gotcha:** a custom `callbackPath` must ALSO be honored by `isContinuationRequired()` (overridden in `BaseOpenIDConnectAuthenticator`), otherwise Tomcat's `AuthenticatorBase.invoke()` skips the valve for the unconstrained callback URL and the callback 404s. The override mirrors `FormAuthenticator`'s logic using `getCallbackAction()` and single-arg `matchRequest()` (the two-arg overload doesn't exist in Tomcat 8.5, and common code compiles against both 8.5 and 9.0).
- **Gotcha (the redirect loop):** on Tomcat 9.0.30+ `AuthenticatorBase.invoke()` calls `doAuthenticateExtended()` and `FormAuthenticator` overrides it with form-only logic that only recognizes `/j_security_check`. The Tomcat 90 valve must override `doAuthenticateExtended()` (in `tomcat90/OpenIDConnectAuthenticator.java`) to route to `performAuthentication()`; without it the OIDC callback is treated as an ordinary unauthenticated request, the login page redirects to the OP again, and the browser loops forever (`ERR_TOO_MANY_REDIRECTS`). Tomcat 8.5 has no `doAuthenticateExtended` (its `invoke()` calls `doAuthenticate` directly), so the override must live in the version-specific class, not the common base.
- **HTTPS gotcha:** the sample `web.xml` deliberately has NO `<transport-guarantee>` on `/secure/*`. If you re-add `CONFIDENTIAL`, Tomcat sets the JSESSIONID cookie with the `Secure` flag on the HTTPS login request, and the callback (which is HTTP because `hostBaseURI` is `http://localhost:8080`) arrives without the session cookie, breaking authentication. Keep the flow HTTP-only, or set `hostBaseURI` to the HTTPS URI and register that in the OP.
- The login page gets request attrs `org.bsworks.oidc.authEndpoints` (per-OP `{issuer, name, url}`) and `org.bsworks.oidc.noForm`; the error page gets `org.bsworks.oidc.error` (`{code, description, infoPageURI}`); the session gets `org.bsworks.oidc.authorization` (ID token, access/refresh tokens, etc.).
- `noForm="true"` disables local form login. Username is taken from the `sub` claim by default — override per-valve or per-OP with `usernameClaim` (supports dot notation) and add scopes via `additionalScopes` (e.g. `email`).
- The authenticator only talks to the OP once per HTTP session; it is **not for RESTful apps**.
- Sample `context.xml` contains real-looking dev client secrets — treat as throwaway dev credentials, not production values.
